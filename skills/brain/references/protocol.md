# Protocol

The read/write contract for a Project Brain. Read this once; it covers storage,
identity, the page model, the caps, and where each kind of knowledge belongs.

## 1. Storage and identity

A brain is **not** stored in the repository. It lives at:

```
$BRAIN_HOME/<project-key>          # BRAIN_HOME defaults to ~/brain.md
```

and contains:

```
<store>/index.md                   # generated by `brain reindex`
<store>/pages/<page-id>.md         # incremental knowledge
<store>/background.md              # six optional root pages
<store>/architecture.md
<store>/flow.md
<store>/mindmap.md
<store>/stack.md
<store>/roadmap.md
```

The `<project-key>` is derived from **project identity**, never from the presence of a
`brain/` directory. The CLI falls back through three identities:

| level | identity | `source:` |
|---|---|---|
| 1 | normalized git remote (`git@github.com:o/r.git` → `github.com/o/r`) | `git-remote` |
| 2 | absolute git common dir | `git-common-dir` |
| 3 | absolute project path | `path` |

The key is `<readable-slug>-<sha256(identity)[0..8]>`, e.g.
`github-com-o-r-1a2b3c4d`. Consequences:

- The same repo keeps one brain across checkouts and worktrees when it has a remote.
- A project without git still works (level 3), as does one without a remote (level 2).
- Running from a subdirectory resolves to the same store (levels 1 and 2).

`brain where` prints the store, home, key, identity, source, whether it exists, and the
page count. There is exactly one store per project — tools never create a shadow copy.

`brain init` creates the store directory and index, and is idempotent. It never
overwrites an existing store.

## 2. Pages — one proposition each

A page is one durable unit of knowledge:

```markdown
---
id: markdown-over-sqlite        # must equal the filename, kebab-case
title: Store config as Markdown
category: decision              # project | concept | decision | person | organization | reference
status: active                  # active | draft | archived
tags: [config, storage]         # optional inline array
created: "2026-01-01T10:00:00"
updated: "2026-01-01T10:00:00"
---

<!-- compiled_truth -->

<the current best understanding — rewritable as a whole>

## Timeline

- time: 2026-01-01T10:00:00
  kind: decision               # decision | evidence | reversal | note
  summary: <one line, in the user's working language>
  source: <where it came from>
  affects: [markdown-over-sqlite]
```

- **compiled_truth** is the current understanding. It is rewritten wholesale by
  `update-truth`, which appends exactly one `decision` timeline entry in the same
  atomic write and bumps `updated`.
- **timeline** is append-only provenance. `append-timeline` only adds to the end;
  existing entries are never edited. Use `kind: reversal` when a conclusion is
  overturned.
- The CLI always writes the canonical markers `<!-- compiled_truth -->` and
  `## Timeline`. A page without them is treated as corrupt, not silently migrated.
- `compiled_truth` must not itself contain a top-level `## Timeline` heading: that
  heading delimits the section and ends the truth body.

### The caps that enforce "one page, one proposition"

`append-timeline` refuses to append when the page already has:

- **30** timeline entries in total, or
- **15** entries whose `kind: decision`.

`--force` overrides the check. `update-truth` is **never** refused — rewriting the
truth is the intended way to consolidate a page back down; splitting knowledge into a
new page and archiving the old one are the other two ways out.

### Archived pages are pointers

```
brain archive-page --id old --superseded-by new --reason "superseded by the new scheme"
```

sets `status: archived` and replaces the page body with a pointer
(`> Superseded by [[new]].`). Archived pages are **read-only**: `update-truth`,
`append-timeline`, `set-tags`, and `archive-page` all refuse them. Read them freely;
their purpose is to preserve the trail, not to be edited.

## 3. Root pages — six fixed slots

`background` / `architecture` / `flow` / `mindmap` / `stack` / `roadmap` hold
project-wide knowledge. They are created **on demand** by the first
`brain update-root <slug>` that has real content. The stdin body must start with an
authored `# Title`; the CLI regenerates frontmatter from it. Root pages have no
timeline — history lives in the store's own git, if the user keeps one. Prefer
` ```mermaid ` diagrams where they clarify structure.

## 4. Choosing where to write

- Changes positioning, architecture, stack, or roadmap → rewrite the matching root page.
- About one entity (decision, concept, person, organization, reference) → create or
  update a page.
- A single discussion often touches both — write both.

Nothing that is pure implementation detail, or plainly readable from the code and
commit history, belongs in the brain.

## 5. Command contract

| intent | command |
|---|---|
| locate the brain | `brain where` |
| create the store | `brain init` |
| list pages | `brain list-pages` → `id  category  status  entries  decisions  title` |
| read a page | `brain read-page <id>` |
| read a root page | `brain read-root <slug>` |
| create a page | `brain create-page --id … --category … --title … [--summary …] [--tags a,b] [--status …] [--source …]` |
| rewrite the truth | `brain update-truth --id <id> [--summary …] [--source …]` (new truth on stdin) |
| append provenance | `brain append-timeline --id <id> --kind <k> --summary … [--source …] [--affects a,b] [--force]` |
| retire a page | `brain archive-page --id <id> [--superseded-by <id>] [--reason …]` |
| change tags | `brain set-tags --id <id> --tags a,b,c` |
| rewrite a root page | `brain update-root <slug>` (body on stdin, starts with `# Title`) |
| rebuild the index | `brain reindex` |
| verify links | `brain lint-links` |

`create-page` and `update-truth` reindex automatically. Write commands never touch the
timeline entries already stored.

## 6. Language

Reply and write in the user's working language. `--summary` is **caller-authored**:
the CLI never generates a sentence. If you omit it, `create-page` uses the page title
and `update-truth` uses the first usable line of the new compiled_truth. Schema keys,
section markers, and enum values stay English.

## 7. Why there is no validator

Correctness is structural: frontmatter is only ever generated by the CLI, and
`update-truth` writes the new understanding and its timeline entry atomically, so
"understanding changed with no trace" cannot happen. That guarantee holds only while
nobody hand-edits a brain file. `reindex` and `lint-links` are optional hygiene, not
load-bearing gates.
